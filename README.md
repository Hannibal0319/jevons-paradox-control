# Jevons' Paradox as a Safety-Critical Control Problem

Reproducibility package for:

> P. Zsoldos, "Jevons' Paradox as a Safety-Critical Control Problem: Consistent
> Rebound Dynamics and the Feasibility Limits of Fiscal Feedback," submitted to
> the 2027 American Control Conference (ACC).

Every number, table, and figure in the paper is generated by the code here.
Nothing in the paper is asserted without a corresponding computation in this
repository.

## What's here

```
paper/
  main.tex        the manuscript
  main.pdf        compiled PDF
model.py          the scalar rebound plant (Eq. 3) and all controllers
                  -> produces Table II and Table III exactly
figures.py        self-contained script -> produces Fig. 1-4 (fig_*.pdf)
tables.py         prints Table II and Table III to the console
figures/          the four figures as embedded in the paper
requirements.txt
```

`model.py` and `figures.py` are two independent implementations of the same
plant. `model.py` is the fuller simulation suite (delay history, Taylor and
Smith predictors, Monte Carlo-ready) used for Table II and Table III;
`figures.py` is a compact, from-scratch recomputation used to render the
paper's four plots at their final size and typography. Where both compute the
same quantity they agree to within simulation tolerance (typically <1%) --
this cross-check is itself part of what makes the numbers trustworthy, and
`figures.py` prints its own agreement check against the paper's stated
values on every run.

## Reproducing the paper

```bash
pip install -r requirements.txt

python tables.py     # Table II (controller performance) and Table III
                      # (residual oscillation vs. reporting delay)

python figures.py    # Fig. 1 (mechanism), Fig. 2 (feasibility obstruction),
                      # Fig. 3 (delay margin), Fig. 4 (controller trajectories)
```

`tables.py` output should match `paper/main.tex` Tables II and III to the
digit. `figures.py` prints the key derived constants (breach time, peak
required tax, the exact delay margin $h^\ast \approx 0.941680$, closed-loop
peak $N$) alongside the values quoted in the paper, so a mismatch is visible
immediately rather than hidden in a plot.

## What maps to what

| Paper artifact | Source |
|---|---|
| Prop. 1, 2 (backfire condition, Jevons signature) | `figures.py`, panel (a)/(b) of Fig. 1 |
| Prop. 3, Cor. 1 (feasibility obstruction, $\eta_{\rm crit}=0.948$) | `figures.py` -> Fig. 2; `model.py` for the $\eta$-sweep |
| Thm. 1, Prop. 4 (exact delay margins $h^\ast$, $\pi/2$) | `figures.py` -> Fig. 3(a), via Newton continuation on the characteristic equation (not a closed-form shortcut) |
| Table II (controller performance) | `model.py` via `tables.py` |
| Table III (residual oscillation vs. delay) | `model.py` via `tables.py` |
| Fig. 4 (controller trajectories) | `figures.py`, a real delayed closed loop (Smith predictor across the $\tau_d=1$ yr window, not an idealized no-delay stand-in) |

## Calibration

All scripts use the calibration of Table I in the paper ($N^\ast$ normalised
to $460$ TWh/yr from IEA data-centre projections; see the paper for sources
and justification of every parameter). Changing a parameter in `model.py` or
`figures.py` and re-running is the fastest way to check the robustness claims
in the paper's Numerical Results section.
